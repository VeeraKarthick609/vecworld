# Dream Roam Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Third-person free roaming through a dreamed world organised by meaning. 360° painted spots with depth, a walking character, camera-relative WASD with mouse orbit, places in compass directions with signposts, and speculative pre-dreaming of the next spot in three directions. Runs on the 4 GB laptop.

**Architecture:** A new `vecworld.roam` package on the server:
- `depth`: 360° depth stitching
- `spot`: builds first/next spots from the existing `TurboPainter`
- `places`: neighbours, bearings, drift and arrival
- `service`: sessions and speculative prefetch, through an extended `GpuQueue`

FastAPI serves spots as JPEG + PNG depth. A three.js viewer in `web/` (vendored three.js + the CC0 robot GLB) builds depth meshes in a Web Worker, moves the character and orbits the camera, and crosses spot edges with an aligned crossfade. Dream Walk's panorama UI, labels and CLIPSeg are removed at the end.

**Tech Stack:** Python 3.12 (uv), PyTorch + CUDA, diffusers (SD-Turbo via the existing painter), transformers (Depth Anything V2 Small, Qwen2.5-1.5B-Instruct), FastAPI, three.js 0.160 (vendored), pytest + selenium (headless Firefox), and puppeteer-core from the Mac for visual end-to-end checks.

**Spec:** `docs/superpowers/specs/2026-10-19-roam-design.md`. Spikes on the laptop: `/tmp/pano3d/` (`gen.py` 360° depth stitch, `index.html` free-roam viewer) and `/tmp/roadspike/viewer/index.html` (character, walk cycle, depth mesh with edge cut and backdrop). They're references for the maths, not code to copy blindly.

## Global Constraints

- **Where:** everything runs on the laptop (`ssh gpu`, repo `~/dev/vecworld`, branch `roam`). No paid or hosted model APIs, no Docker. Commits carry **no Co-Authored-By or Claude attribution**. Push after every commit.
- **GPU:** peak allocated VRAM **< 3.6 GB** with the painter and depth model resident together (depth falls back to the CPU only if that's impossible). The dreamer LLM runs on the CPU with capped threads, and text encoding for painting has priority.
- **Panorama:**
  - 2048×512 cylindrical, 360° horizontal × 90° vertical, from the existing `TurboPainter` (`panorama`, `step` with `focus`/`focus_at`/`bg_strength`), which already has the final-review fixes.
  - STYLE and MOOD_WORDS are reused from config.
  - The panorama prompt asks for open ground near the viewer.
- **360° depth:**
  - Depth Anything V2 Small on 8 overlapping 512-px slices, stride 256, wrapping.
  - Each slice is least-squares scale+shift aligned to the previous one on the overlap.
  - The loop-closure error is spread linearly, slices are blended with triangular weights, and the result is normalised by the 1st/99th percentile into 0..1 (1 = near).
  - Delivered as an 8-bit PNG.
- **Viewer geometry:**
  - Column u maps to heading θ = (u − 0.5)·2π, where u = 0.5 is the spot's forward direction.
  - Row v maps to height (0.5 − v)·π/2 on the unit cylinder.
  - Radius = `1/(d·(1/NEAR − 1/FAR) + 1/FAR)`, NEAR = 4, FAR = 50.
  - Triangles whose radius ratio exceeds 1.35 are cut, a backdrop cylinder sits at FAR, and there is a ground surface (no void below).
- **Character and camera:**
  - CC0 RobotExpressive with Idle/Walking blended by speed. Stride 1.1 units per walk cycle, Shift ×1.8 with the animation sped up.
  - Movement is camera-relative, and the character turns toward its direction of travel.
  - The camera orbits at distance 1.9, height 0.55, with pitch limited to −0.1…0.45. Drag or pointer-lock, Esc releases.
- **Pace and pre-dreaming (the user's choice):**
  - Brisk walking.
  - On entering a spot, pre-dream the next spot at the heading and ±60° (heading first).
  - Re-target as the heading changes. Finished spots within 45° of a candidate are kept.
  - At the edge, use the finished spot closest to the exit heading within 45°. Otherwise show dream fog and build the exact heading at demand priority.
- **Places:**
  - 2–4 neighbours at bearings assigned by code (spread around the compass from a random offset). The place you came from is always behind your arrival direction.
  - Drift completes over 3 spots built within ±45° of a neighbour's bearing. Then you arrive, and the colour reference moves gradually.
  - The LLM only names neighbours and the in-between scenery. A fallback table covers the time before it answers.
- **Latency**, single player: start to first spot ≤ 6 s. Several players queue fairly, and fog covers the waits.
- **Viewer frame rate:** full frame rate on a desktop. Spot meshes are built in a Web Worker.
- **Assets:** three.js and the GLB are bundled under `web/vendor/`, not loaded from a CDN at runtime.
- **Test markers:** `gpu` (real models) and `ui` (headless Firefox). The default run excludes both. The game server holds the GPU, so stop it with `pkill -f "python3? -m [v]ecworld"` before GPU tests.

## Review Focus

1. **Turning sharply right after entering a spot,** so none of the three pre-dreamed directions matches the exit. Expected: no wrong-direction spot is ever shown, fog appears, and the exact heading is built at demand priority. *(Task 6: `test_exit_far_from_all_prefetches_builds_on_demand`)*
2. **Theme or mood change while pre-dreamed spots exist.** Expected: no stale spot is shown. *(Task 6: `test_mood_change_discards_predreamed_spots`)*
3. **Walking back the way you came.** Expected: the "came from" place is behind you and the world continues; no crash on a 180° exit. *(Task 4: `test_came_from_is_behind_arrival`; Task 6: `test_exit_backwards`)*
4. **A depth slice that's nearly flat,** e.g. sky or fog, which makes least-squares alignment ill-conditioned. Expected: no NaN or inverted depth, and the stitch still produces a sane 0..1 map. *(Task 1: `test_flat_slice_does_not_break_alignment`)*
5. **The player keeps walking into an edge while fog waits on a slow GPU.** Expected: the character holds at the edge, nothing breaks, and the walk continues when the spot arrives. A request failing (503) leaves the current spot playable. *(Task 8: `test_edge_waits_in_fog_then_continues`, `test_failed_next_keeps_current_spot`)*

### Task 2: Spot builder

**Files:**
- Create: `src/vecworld/roam/spot.py`
- Test: `tests/test_spot.py` (fakes), `tests/test_spot_gpu.py`

**Interfaces:**
- Consumes: `TurboPainter`/`Painter` (`dream/painter.py`), `pano.roll_to`, `pano.yaw_to_u`, `pano.dolly`, `palette.palette_stats`/`match_palette`, Task 1 `DepthEstimator`.
- Produces:
  - `@dataclass(frozen=True) class Spot: id: str; image: Image.Image; depth: np.ndarray; heading: float; scale: float`. `heading` is the world bearing (degrees) of the spot's forward direction (u = 0.5). `scale` is the world-units multiplier that aligns this spot's depth to its parent.
  - `def first_spot(painter, depth, prompt: Prompt, seed: int) -> Spot` (heading 0, scale 1)
  - `def next_spot(painter, depth, parent: Spot, exit_heading: float, base: Prompt, focus: Prompt | None, seed: int, ref: Stats | None, bg_strength: float | None = None) -> Spot`. It:
    1. rolls the parent to `exit_heading − parent.heading`;
    2. dollies;
    3. calls `painter.step` with focus at 0.5;
    4. applies the palette pull toward `ref`;
    5. runs `depth360`;
    6. sets `scale = align_scale(parent, child, rel_heading)`.
  - `def align_scale(parent: Spot, child: Spot, rel_heading: float) -> float`: compares the median radius of the parent's view around `rel_heading` (±30°) with the child's view around its forward direction (±30°), adjusted by the dolly distance, and returns the multiplier for the child's radii. Uses the radius formula from Global Constraints.
  - `def dolly_distance(z: float = DOLLY) -> float`: world distance the dolly represents. The forward median radius of the view × (1 − 1/z) is acceptable; it's used to place the child.

**Interfaces:**
- Produces: `submit_set(jobs: list[tuple[str, Callable[[], T]]], owner: str) -> dict[str, Future[T]]`. These are keyed prefetch jobs. The call replaces that owner's queued, not-started prefetch jobs whose keys aren't in the new set, and keeps already queued or running jobs whose keys are in the set (returns their futures). Order inside the set is preserved (heading first). `submit(..., prefetch=True)` keeps working as a one-job set.

    - `heading(sid, heading)` (a hint that re-targets the pre-dream set)

    - Version bump on mood or theme change discards the set.
    - Reuses TTL/LRU, busy guard, 503 on OOM (the session unchanged), JPEG + PNG files kept for the last 3 spots, and file cleanup on eviction.
